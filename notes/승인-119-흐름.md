> 10/8: 승인 알림에 CCTV 캡처를 붙임 (`notify_guardian.value.cctv_image`, `cctv_check` = fall / unavailable).
>
> 10/8 변경: 어르신 확인을 스피커 대신 워치 버튼으로 바꿈 ("괜찮아요" / "도와주세요" / 30초 안에 안 누름).

코드: `backend/src/rules/risk.py` (`auto_119_reason`, `select_actions`, `after_guardian_timeout`),
`backend/src/llm/fallback.py` (알림 문구), `backend/src/llm/prompts.py` (Summary 상황) · 테스트: `backend/tests/test_escalation.py`
모든 시간·기준은 **시연용 설정값**이며 실제 서비스는 응급 전문가 검토 후 정해야 함.

## 1. 한눈에

```
판정(코드) ──┬─ 정상 ───────────────→ 종료 (알림 없음)
             │
             ├─ 승인할 조치 없음 ────→ 📱 상태 알림 (+ 워치 버튼 확인) → 2차 판정
             │   (낙상 의심, 산소포화도 조금 낮음 등)
             │
             ├─ 승인 필요 ───────────→ 📱 승인 요청 ─┬─ 승인 → 실행 → Summary
             │   (기기 제어, 119)                    ├─ 거절 → 기록 → Summary(보호자용만)
             │                                       └─ 30초 무응답 → 📱 다시 알림
             │                                            └─ 60초 무응답 → 119만 자동 연결, 기기는 계속 대기
             │
             └─ 정말 위급 ───────────→ ☎️ 119 바로 연결 → 📱 긴급 알림 ("연락했습니다") → Summary
```

## 2. 119 바로 연결 (승인 없이)

위험도가 **위급**이고 아래 둘 중 하나일 때만.

| 이유 코드 | 조건 | 왜 |
|---|---|---|
| `ELDER_NO_RESPONSE` | 워치 확인에 어르신이 30초 안에 버튼을 누르지 않음 (`fall_event.watch_response = "none"`) | 의식이 없을 수 있어 1분 1초가 중요. 애플워치 낙상 감지도 무응답이면 자동 신고 |
| `VITAL_SEVERE` (기본 꺼짐) | 바이탈 위험 범위 2개 이상 **그리고** 4항목 점수 합 7점 이상, 최신 측정값. 확정안 critical은 "119 승인" 장면이라 `ENABLE_AUTO_119_VITAL = False` | NEWS2는 합 7점 이상을 "긴급 대응"으로 봄 (7항목 기준, 출처 확인 필요) |

자동 연결 안 함: 이전 측정값(캐시)일 때 (워치가 빠졌거나 센서 오류일 수 있음), "도와주세요" 응답(말을 할 수 있음 → 보호자 승인 + 60초 자동).

조치 형식: `{"type": "call_119", "needs_approval": false, "auto": true, "auto_reason": "ELDER_NO_RESPONSE"}`

## 3. 승인 대기와 시간 초과

| 조치 | 승인 | 응답 없을 때 (`on_timeout`) |
|---|---|---|
| 119 호출 (위급) | 필요 | 60초 뒤 **자동 연결** (`execute`) |
| 기기 제어 (에어컨·인덕션) | 필요 | 실행 안 함, 다시 알림 (`remind`) |
| 워치 확인·병원 정보·보호자 알림 | 없음 | 바로 실행 |

`after_guardian_timeout(actions)` → `{"execute": [119], "remind": [기기]}`

## 4. 보호자 휴대폰 알림 (모두 코드 템플릿, LLM 안 기다림)

| 언제 | `notify_guardian.value.kind` | 문구 함수 |
|---|---|---|
| 승인 요청 | `approval_request` | `pending_guardian_message()` (119가 있으면 "60초 안에 응답이 없으면 119에 자동으로 연락합니다") |
| 30초 무응답 | 같은 알림의 재알림 (`remind_after_seconds: 30`) | `reminder_guardian_message()` |
| 119 바로 연결 직후 | `emergency_alert` | `emergency_alert_message()` ("[긴급] 어르신이 워치 확인에 응답하지 않아 119에 바로 연락했습니다…") |
| 승인할 조치 없음 | `info` | 상태 알림 |

결과 안내(Summary, LLM) 상황: `done` / `rejected` / `device_fail` / `info` / `auto_119` / `timeout_119`.
`auto_119`·`timeout_119`는 "승인하신"처럼 보호자가 승인한 것처럼 쓰면 검증에서 걸림.

## 6. 남은 걱정 (시연 뒤 실제 서비스라면)

- 밤에 자고 있거나 워치를 빼 둔 경우도 "무응답"이 됨 → 누워 있음 + 무응답은 워치 진동으로 한 번 더 묻기 등 2단계 확인 검토.
- 119 오신고 비용과 보호자 불안. 바로 연결 조건은 좁게 두고, 나머지는 보호자 승인 + 시간 초과로.
