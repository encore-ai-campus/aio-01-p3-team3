# 낙상 판정 케이스표 (해든 설계 10/8, 4단계)

코드: `backend/src/rules/risk.py`의 `detect_fall()` · 테스트: `backend/tests/test_fall_cases.py` (번호 F1~F25가 같음)
모든 시간·기준은 **시연용 시스템 설정값**이며, 실제 서비스는 의료·응급 전문가 검토 후 정해야 함.

## 1. 핵심 원칙

- 낙상은 바이탈과 **따로 판정하는 축**이다. 바이탈이 정상이어도 낙상 축만으로 위급이 될 수 있다.
- 판정 축 4개 (해든 분류 10/8): `fall`(낙상·보행), `cardio`(심박·혈압 + 이상 행동), `respiratory`(SpO2 + 호흡 곤란 정황), `environment`(실내 온도·체온·인덕션 + 에어컨/보일러). 위험 범위 항목 2개 이상이면 축이 달라도 위급
- 최종 위험도 = 가장 높은 축 (정상 < 주의 < 경고 < 위급) → 취약도 "상"이면 한 단계 올림 (정상은 그대로, D1)
- LLM은 판정하지 않는다. 골절·뇌진탕·의식 상태처럼 사진으로 알 수 없는 것은 쓰지 않고, "낙상 의심과 무응답이 감지되었습니다"처럼 관찰 사실만 전달한다.

## 2. 낙상 상태 5개

| 상태 | 뜻 | 낙상 축 단계 | 시스템 행동 |
|---|---|---|---|
| `none` | 낙상 신호 없음 | 정상 | — |
| `false_alarm` (오탐 가능) | 약한 신호 뒤 서 있거나 앉은 모습, 또는 "괜찮다"는 응답 | 정상 | 근거에 기록만 |
| `suspected` (의심) | 워치만, 흐린 사진, 바닥에 앉았을 수 있음 등 확인이 안 된 신호 | 경고 | 보호자 알림, 스피커 확인 |
| `confirmed` (확인) | CCTV가 바닥 자세를 분명히 봄, 도움 요청 음성, 오래 움직임 없음 | 위급 | 119 승인 화면, 병원 정보, 스피커 확인(응답 모를 때) |
| `critical` (위급) | 무응답, 머리 충격 의심, 또는 바이탈 위험 범위 동반 | 위급 | 위와 같음, 근거에 위급 신호 표시 |

## 3. 시연 입력과 README의 차이 (기본값으로 정한 것)

| 해든 설계 | README 시연에 있나 | 기본값 |
|---|---|---|
| 워치 낙상 감지 | 없음 | `care_status["fall_event"]["watch_fall"]`로 받을 수 있게만 둠. 없으면 "모름" |
| 음성 응답 | 없음 (스피커 기기 없음) | `fall_event["voice_response"]` = `ok` / `help` / `none`. 없으면 "모름" → `speaker_check` 조치를 넣음 |
| 바닥 체류 시간 | 사진 한 장이라 알 수 없음 | `fall_event["immobile_seconds"]`. 60초 이상이면 "오래 움직임 없음" |
| 머리 충격 의심 | 없음 | `fall_event["head_impact_suspected"]` (워치 충격 센서 등). CCTV LLM은 판단하지 않음 |
| 낙상 확신도 | 없음 | CCTV 결과에 `confidence`(`high`/`low`) 1개 추가. 없으면 `high` |
| README "쓰러짐 의심 → 위급" | 있음 | **CCTV가 바닥 자세를 분명히 볼 때만** 위급. 흐린 사진·자세 불일치는 의심(경고)으로 낮춤 |
| D3 "lying만으로는 안 올림" | 계획서 결정 | 그대로 유지. lying + 무응답 또는 60초 이상 움직임 없음일 때만 의심 이상 |

README fall 시나리오(바닥 자세, 확신 높음)는 지금처럼 **위급 + 119**로 나온다. 바뀐 점은 조치에 "스피커로 상태 확인"이 하나 더 들어간 것.

- F20: 취약도 보정으로 위급이 되면 낙상 신호가 의심 수준이어도 119 승인 버튼을 보여준다 (승인은 보호자가 함).

## 5. 스피커 확인 흐름 (확장, 시연에서는 mock)

```
1. CCTV(또는 워치)가 낙상 신호를 보냄 → 1차 판정 (음성 응답 모름 → speaker_check 조치 포함)
2. 스피커: "괜찮으신가요? 도움이 필요하면 말씀해 주세요."
3. 30초 동안 응답 확인 (SPEAKER_WAIT_SEC, 시연용)
4. fall_event.voice_response를 넣어 2차 판정
   - ok + 서 있거나 앉음 → 오탐(기록) / ok + 바닥 → 확인(위급 유지)
   - none → 위급 / help → 확인(위급)
```
