# 두나 담당 구현 계획 및 최종 함수 계약

## 1. 담당 범위

두나는 다음 두 영역을 담당한다.

1. 시나리오별 Mock 데이터와 MCP 도구 9개
2. 보호자 승인 화면과 `/care/run` → `/care/approve` 연동

지혜가 정의한 Pydantic 스키마를 API 계약으로 사용하고, 해든이 구현하는 CCTV 분석 함수를 MCP 도구로 연결한다.

## 2. 확정된 공통 이름

| 구분 | 사용할 이름 |
| --- | --- |
| 가상 어르신 식별자 | `profile_id` |
| 실행 식별자 | `run_id` |
| 시나리오 | `scenario` |
| 장애 목록 | `fault` |
| 승인 결정 | `decision` |
| 승인 | `"approve"` |
| 거절 | `"reject"` |

`person_id`, `task_id`, `approved: true/false`는 사용하지 않는다.

## 3. 시나리오

```python
from typing import Literal

Scenario = Literal["normal", "heat", "induction", "fall"]
```

시나리오별 Mock 데이터는 다음 파일에 작성한다.

```text

```

### 4.5 `analyze_cctv`

해든이 구현하는 안전 래퍼 함수 계약은 다음과 같이 확정한다.

```python

    ...
```

두나는 내부 분석 함수를 수정하거나 다시 구현하지 않고 안전 래퍼를 MCP 도구에서 호출한다.

```python
from src.vision.analyzer import analyze_cctv_or_unavailable


@mcp.tool()
def analyze_cctv(image_path: str) -> dict:
    return analyze_cctv_or_unavailable(image_path)
```

정상 분석 결과:

```json
{
  "image_path": "assets/cctv/fall.jpg",
  "person_visible": true,
  "posture": "fallen",
  "fall_suspected": true,
  "description": "거실 바닥에 사람이 쓰러져 있는 것으로 의심됩니다.",
  "confidence": 0.96
}
```

분석할 수 없는 경우에도 같은 필드를 유지한다.

```json
{
  "image_path": "assets/cctv/fall.jpg",
  "person_visible": false,
  "posture": "none",
  "fall_suspected": false,
  "description": "영상 판단 불가",
  "confidence": 0.0
}
```

`posture`는 `standing`, `sitting`, `lying`, `fallen`, `none` 중 하나이고, `confidence`는 `0` 이상 `1` 이하의 숫자다.

## 5. MCP 구현 원칙

- 모든 도구는 실제 개인정보가 아닌 Mock 데이터만 사용한다.
- `control_device`, `notify_guardian`, `call_119`는 실제 외부 동작을 수행하지 않는다.
- 지원하지 않는 `profile_id`, `scenario`, `device`, `action`은 임의의 기본값으로 처리하지 않고 예외를 발생시킨다.
- AutoHealing이 오류를 감지할 수 있도록 도구 내부에서 예외를 숨기지 않는다.
- 함수명, 매개변수명, 반환 키는 이 문서와 동일하게 유지한다.
- 서버 전역 변수로 현재 시나리오를 관리하지 않는다. 각 조회 호출에 `scenario`를 명시적으로 전달한다.

## 6. 승인 API 계약

### 6.1 `POST /care/run`

요청:

```json
{
  "profile_id": "profile-01",
  "scenario": "fall",
  "fault": ["vision"]
}
```

응답의 주요 필드:

```python
run_id = response["run_id"]
status = response["status"]
current_step = response["current_step"]
care_status = response.get("care_status")
emergency = response.get("emergency")
message = response.get("message")
```

`status`는 다음 중 하나이다.

```python
Literal["no_issue", "pending_approval", "done", "rejected", "fail"]
```

### 6.2 `POST /care/approve`

요청:

```json
{
  "run_id": "run-001",
  "decision": "approve"
}
```

`decision`은 `approve` 또는 `reject`만 사용한다.

승인 API는 동기 방식으로 처리한다. 백엔드는 승인된 Mock Action 실행까지 마친 뒤 최종 결과를 반환한다.

응답 `status`는 다음 중 하나이다.

```python
Literal["no_issue", "pending_approval", "done", "rejected", "fail"]
```

| 상태 | 의미 |
| --- | --- |
| `done` | 승인 후 모든 Mock Action 실행 완료 또는 자동 119 완료 |
| `rejected` | 보호자가 조치를 거절함 |
| `fail` | 승인됐지만 Mock Action 실행 중 실패함 |

중간 상태인 `approved`는 사용하지 않는다.

```python

```

승인 화면 함수:

```python
def render_approval_panel(
    run_response: dict,
    backend_url: str,
) -> None:
    ...
```

`status == "pending_approval"`이면 다음 값을 Streamlit 세션 상태에 저장한다.

```python
st.session_state["run_id"] = run_response["run_id"]
st.session_state["care_status"] = run_response.get("care_status")
st.session_state["emergency"] = run_response.get("emergency")
```

승인 화면에는 다음 내용을 표시한다.

- 현재 단계
- 위험도
- 판정 근거
- 제안된 조치 목록
- CCTV 이미지
- CCTV 분석 요약
- 승인 버튼
- 거절 버튼
- 승인 또는 거절 후 최종 실행 결과

## 9. 완료 기준

- MCP 서버의 도구 목록에서 9개 도구가 모두 확인된다.
- MCP 함수명과 `ProposedAction.tool` 값이 일치한다.
- `ProposedAction.arguments`의 키와 MCP 함수 매개변수명이 일치한다.
- 다섯 가지 시나리오가 모두 최신 Mock 데이터를 반환한다.
- 세 명의 Mock 프로필이 README의 나이·독거·지병 유무·거동 불편 계약과 일치한다.
- 바이탈에는 수축기 혈압만 사용하고 `diastolic_bp`를 포함하지 않는다.
- 인덕션 시나리오에서 `induction_minutes=120`, `induction_temperature=300`을 반환한다.
- CCTV 분석 결과가 `CctvAnalysis` 형식으로 반환된다.
- `/care/run`의 `run_id`가 `/care/approve`에 그대로 전달된다.
- 승인 또는 자동 119 완료는 `done`, 거절은 `rejected`, 실패는 `fail`로 표시된다.
- 승인 화면은 도구 이름 추론이 아니라 각 조치의 `needs_approval` 값을 따른다.
- Streamlit 재실행 중에도 승인 대기 중인 `run_id`가 세션 상태에 유지된다.
- 단위 테스트와 통합 테스트가 통과한다.
