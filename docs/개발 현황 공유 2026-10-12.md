### 3번, 4번, 6번 설명

- **4번 `fall`**: API 키가 없어 CCTV 분석이 "판단 불가"였고, 바이탈만 보고 경고로 끝났습니다. 키가 있는 환경에서 "CCTV 쓰러짐 감지 → 위급 → 119 승인 요청"이 나오는지 확인이 필요합니다.
- **3번 `induction`**: 같은 이유로 정상 판정이 나왔습니다. 인덕션이 120분·300℃로 켜져 있어도 CCTV를 못 보면 이상으로 보지 않습니다. README는 "정보가 빠지면 더 보수적으로" 판단한다고 했는데, 이 경우는 반대입니다. 키가 있는 환경에서 확인하고, CCTV를 못 봐도 기기 상태만으로 최소한 "주의"로 올릴지 정해야 합니다.
- **6번 `vital` 장애**: 바이탈의 1순위가 시뮬레이터(15초마다 전송)이고, 실패하면 재시도 → 캐시 → MCP mock 순서입니다. 시뮬레이터를 켠 적이 없으면 캐시가 비어서 mock으로 넘어갑니다. "n분 전 측정값" 장면을 시연하려면 **시뮬레이터를 먼저 켜 두어야** 합니다. 시뮬레이터가 꺼져 있으면 모든 실행이 먼저 약 2초를 쓰고 mock으로 넘어갑니다.
