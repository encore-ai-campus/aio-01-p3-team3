# 두나 점검 결과 — 팀원별 전달 사항

2026-10-12, 두나가 README와 코드를 대조하고 Docker·CCTV 경로를 확인하면서 찾은 내용입니다.
두나 담당(mock 데이터, MCP 도구, 승인 화면)은 이미 고쳤고, 아래는 **각 담당분이 확인하고 고쳐 주셔야 하는 것**입니다.
테스트는 backend 431개, mcp_server 128개, frontend 21개가 모두 통과합니다. 아래 문제는 테스트가 잡지 못한 것들입니다.

## 결정 사항: 119 자동 연결은 `critical` 상황에서만 쓴다 

README와 `docs/scenarios.md`가 맞고, 코드를 거기에 맞춰야 합니다.

- **자동 연결 조건**: README 5·9장 그대로입니다. 위급이면서 바이탈 위험 범위(3점) 2개 이상, 점수 합 7점 이상, 최신 측정값(캐시 아님)일 때만 승인 없이 119에 연결합니다. `critical` 시나리오가 이 조건에 해당합니다.
- **그 밖의 119**(`fall` 등)는 모두 보호자 승인을 받습니다.
- 지금 코드는 반대로 꺼져 있어서 `critical`도 승인 요청으로 갑니다. 시연 시나리오 5번과 8번이 README대로 나오지 않는 상태입니다.

## 지혜 (backend / 오케스트레이터)

1. **`GET /cctv/{name}` 라우트가 backend에 없습니다. (승인 화면 캡처가 안 나오는 원인)**
   - frontend는 `BACKEND_URL/cctv/{파일명}`을 호출합니다. 이 경로는 MCP 서버에만 있습니다.
   - 그래서 승인 화면에 "CCTV 이미지를 표시할 수 없습니다" 경고가 뜹니다.
   - 제안: backend가 MCP 서버의 `/cctv/{name}`을 받아서 그대로 돌려줍니다.
     - MCP 주소는 `MCP_URL`에서 끝의 `/mcp`를 뗀 값입니다. 예: `http://mcp:8010/cctv/fall.png`
     - MCP가 404면 backend도 404, 연결 실패면 503으로 응답하고 `content-type`은 그대로 전달합니다.
     - `httpx`는 이미 `backend/requirements/runtime.txt`에 있습니다.
   - `backend/tests/test_api.py` 맨 위 설명에 `/cctv/{name}` 테스트가 예정되어 있었는데 아직 없습니다.
2. **README 11장 API 명세와 코드가 다릅니다.**
   - `GET /logs`: README에는 있고 코드에는 없습니다.
   - `GET /health/ready`, `POST /vitals/readings`: 코드에는 있고 README에는 없습니다.
3. `decided_by` 값에 `"timeout"`이 있는데 README에는 `guardian`/`auto`만 적혀 있습니다. 위 "결정 사항"의 timeout 정리와 함께 처리해 주세요.

## 해든 (LLM / 위험도 규칙 / CCTV 분석)

1. **119 자동 연결 flag를 켜 주세요.** 위 "결정 사항"에 작업 목록이 있습니다. (`risk.py:114-119`)
2. **CCTV 파일 형식이 .jpg에서 .png로 바뀌었습니다.** (커밋 `5375aff`에서 `.jpg` 8개를 삭제하고 `.png` 4개만 남김)
   - 두나는 `mock_data.py`의 경로를 `.png`로 맞췄습니다. 비전 분석은 Pillow가 PNG를 JPEG으로 변환해서 보내므로 그대로 동작합니다.
   - `notes/make_fake_cctv.py`는 아직 `.jpg`로 만들고 `notes/cctv_check.py`는 `*.jpg`만 찾습니다. 다시 실행하면 `.jpg`가 되살아납니다.
   - `.jpg`를 쓸지 `.png`를 쓸지 팀에서 하나로 정해 주세요. 지금은 backend 테스트의 가짜 데이터(`test_care_run.py`, `test_integration.py` 등)가 `.jpg` 이름을 쓰고 있어 실제 파일과 이름이 다릅니다. 테스트는 통과하지만 헷갈립니다.
3. 아직 해든 님 쪽 실제 API 응답으로 확인하지 못했습니다. 지금까지의 CCTV·LLM 테스트는 전부 mock 기반입니다. 키를 넣은 end-to-end 실행을 한 번 해보시길 권합니다.
