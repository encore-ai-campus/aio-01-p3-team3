# 보호자 프런트엔드 디자인 및 확인 방법

브랜치: codex/guardian-frontend. 기존 로그인·승인·세션 상태·API 계약을 유지한다.
참고 화면의 파란 배너, 흰 배경 카드와 둥근 버튼을 프로젝트용 HTML·CSS로 적용했다.
CSS는 frontend/assets/dashboard.css, 앱에서 읽으며 Dockerfile도 assets를 복사한다.
새 가상 진행 애니메이션 없이 backend current_step을 표시한다.

## 화면 순서

로그인 → 안내 배너·어르신 정보 → 진행 표시 → 바이탈/실내/CCTV 카드
→ 위험도·조치 승인·결과 → 해당 실행 AutoHealing 로그.
CCTV는 상태 카드로 통합하며 승인 패널에서 중복 출력하지 않는다.
누락값·캐시 출처·분석 실패를 표시하고 이미지 실패가 전체 화면을 중단하지 않는다.
승인 판단에 불필요한 원시 도구 인자는 화면에서 제거했다.

## 로컬 확인

frontend에서 실행한다.

```powershell
$env:DEMO_ACCOUNTS="demo:demo123:profile-02"
python -m streamlit run src/app.py --server.port 8501
```

http://127.0.0.1:8501에서 demo/demo123으로 로그인한다.
버튼 기능은 backend 8000·MCP 8010 실행도 필요하다.
backend: `python -m uvicorn src.main:app --host 127.0.0.1 --port 8000`
mcp_server: `python -m src.server`
각 폴더의 requirements/runtime.txt가 설치되어 있어야 한다.
실제 비전·문장 모델은 키 설정에 따라 동작하며 키가 없으면 판단 불가·템플릿 경로를 사용한다.

## 검증

Windows에서 한글 AppTest는 UTF-8 모드로 실행한다.
`python -X utf8 -m pytest tests -q`: 51개 통과.
로그인 후 상태 확인 버튼까지 앱 smoke 시험 통과, backend /health/ready 200 확인.
좁은 화면은 CSS 미디어 쿼리와 Streamlit 컬럼 배치로 대응한다.
실제 브라우저 모든 크기의 시각 검수·실제 LLM 실행은 추가 확인 사항이다.
